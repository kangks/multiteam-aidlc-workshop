# Discovered Rules

## Mandated

- ALWAYS commit completed work directly to the shared `main` branch.
- ALWAYS use team-owned Construction for this application.
- ALWAYS divide this application into a health walking-skeleton Unit, a payments feature Unit, and a notifications feature Unit.
- ALWAYS use a walking skeleton when the selected plan calls for one.
- ALWAYS use the health endpoint as this application's first end-to-end Unit.
- ALWAYS write a failing test before each implementation change.
- ALWAYS deploy merges automatically to staging.
- ALWAYS require separate approval before deploying to production.
- ALWAYS use the chosen stack's standard formatter, linter, and idiomatic naming.

## Forbidden

- NEVER make the payments Unit depend on completion of the notifications Unit, or the notifications Unit depend on completion of the payments Unit.
